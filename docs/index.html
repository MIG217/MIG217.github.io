Prompt Caching

我们在讨论 LLM 应用优化的时候，大多数人第一反应是换模型、调参数、改架构。但有一件事几乎被所有人忽略，它不需要改任何模型代码，不影响输出质量，却能让首 Token 延迟最高降低 80%、输出成本最高降低 90%。这件事就是 Prompt Caching。 1. Prompt Caching 基本概念 跟模型打交道，本质上就三件事可以优化：intelligence、latency、cost。三者通常此消彼长，但 Prompt Caching 是个例外：它只动后两个，完全不影响第一个。 模型的提示词中往往包含大量重复内容——系统指令、工具定义、对话历史。OpenAI 会把请求路由到最近处理过相同前缀的服务器，复用之前的计算结果，而不是从头重算。这就是 prompt caching 的本质：计算复用。 它带来的收益： 成本：cached input token 最高便宜 90%（比如 gpt-5.2 从 $1.75/1M 降到 $0.175/1M） 延迟：TTFT（首 token 时间）最高减少 80%，prompt 越长效果越明显 2. Multimodal Autonomous AI Agents

近年来 LLM 取得了令人瞩目的进展。从 上下文学习（in-context learning）、零样本学习（zero-shot learning） 到生成连贯且知识丰富的长文本，LLM 在语言理解与生成方面展现出惊人的能力。 然而，语言模型本身仍然停留在“被动回答”的阶段。真正的智能，应当能够主动行动（Act）、自主决策（Decide）、并完成任务（Execute）。这正是 Autonomous AI Agents 所要实现的目标。 我们的大部分生产性工作都发生在计算机和网络上——撰写文档、处理数据、预订服务、甚至编程与科研。 如果这些任务能被智能体部分或完全自动化，人类的生产力将获得显著提升。 设想一下，一个智能体可以帮你自动配置 AWS 实例、生成论文展示的 PowerPoint、或在网页上查找并预约餐厅。这类系统不再只是回答问题，而是能理解网页结构、分析视觉信息，并执行真实操作。 在众多智能体形态中，Web Agents 是当前研究的核心方向之一。让智能体在复杂的网络环境中执行任务，仅依靠语言理解还远远不够。它必须具备两种关键能力： 文本理解：能够解析网页的 HTML 结构，识别内容层级与交互元素； 视觉理解：能够理解网页截图或 GUI 的视觉布局与语义信息。 通过融合文本与视觉信息，智能体才能在网络上建立起“感知与理解”的能力（即 web grounding），从而正确地解析指令并执行操作。 本文重点：如何构建更可靠的 Web Agent？ 要让 Web Agent 从“演示级”走向“实用化”，还需要解决一系列核心问题。 本文将聚焦三个关键方向： Evaluation：如何在贴近真实网页环境的复杂场景中，科学评估 Multimodal Agents的表现？ Algorithm：在推理阶段，如何利用 Tree Search 等算法提升Agents执行任务的成功率？ Data：Agents 高度依赖高质量数据，如何实现互联网规模的数据采集与训练？

Introduction to training LLMs for AI agents

大家可能都已经对 LLM 很熟悉了。大概在两三年前，ChatGPT、Claude、Llama、DeepSeek 等模型相继出现，可以说是彻底改变了世界。但在使用这些强大工具的同时,一个核心问题值得探讨：这些模型到底是如何训练的？ 本文将从宏观视角梳理 LLM 的训练流程，重点关注训练 AI Agents 所需的关键技术路径,而非底层实现细节。 LLM Training Pipeline LLM 的训练是一项复杂的系统工程,通常可以划分为三个核心阶段: 预训练(Pre-training)、经典后训练(Classic Post-training/RLHF) 和 推理强化学习(RL for Reasoning)。在实际应用中,我们还会结合 提示工程(Prompting) 和 微调(Fine-tuning) 来进一步激发模型潜力。 General LLM Training Pipeline 从整体上看，大语言模型（LLM）的训练分为三个阶段，每个阶段的目标、规模和挑战各不相同： Pre-training：在大规模文本上学习预测下一个词，建立通用知识基础；这是规模最大、成本最高的一步，瓶颈在于高质量数据和算力资源。 Classic Post-training / RLHF：通过人类反馈强化学习，使模型输出更符合用户偏好；相比预训练，所需数据和成本大幅降低，但高度依赖优质反馈和有效评测体系。 RL for Reasoning：让模型在回答前进行推理，提升解决数学、编程等客观问题的能力；规模和成本介于前两者之间，难点在于设计合适的 RL 环境并防止模型“自我黑客”。 三个阶段对比 阶段 核心目标 数据规模 训练时间 成本级别 主要瓶颈 预训练（Pre-training） 学习预测下一个词，构建知识底座 ~10 万亿 tokens 数月 千万美元级 高质量数据、算力资源 经典后训练 / RLHF（Classic Post-training / RLHF） 让模型符合用户偏好 ~10 万个问题 几天 数万–十万美元 人类反馈数据、评测体系 推理型 RL（RL for Reasoning） 提升推理和思考能力 百万级问题 数周 百万美元级 RL 环境设计、防止自我黑客 成功的关键要素 了解了训练的宏观阶段后，我们再深入一层，看看在每个阶段中，哪些要素是决定模型成败的关键。 ...

Mcp Architecture

在当下的 AI 应用开发中，模型本身的智能水平固然重要，但如果无法高效接入外部数据和工具，模型的价值就会大打折扣。很多开发者不得不为不同的数据源、API 或工具重复实现集成逻辑，这不仅增加了开发成本，也让应用难以复用和扩展。 为了解决这一问题，Anthropic 团队与开源社区共同推动了 Model Context Protocol（MCP）。MCP 是一种开放协议，旨在标准化 LLM 应用与外部系统的连接方式，让模型可以像调用 REST API 一样，统一地访问各类工具与数据源。 MCP Architecture MCP 遵循经典的客户端-服务器 (Client-Server) 架构模式。在这个模式中，主要有三个核心角色： Host: 指希望通过 MCP 访问数据的大模型应用，例如 Claude Desktop、IDE、AI Agent 等。 MCP Servers: 是一些 轻量级程序，通过 MCP 协议对外暴露特定功能（capabilities），比如访问数据库、调用搜索服务或执行 API。 MCP Clients: 在宿主应用内部，与 MCP Server 保持 1:1 连接，用于管理通信。 MCP 核心要素 在进一步讨论客户端和服务器的职责之前，我们需要先了解 MCP 协议中几个最核心的组成部分：工具（Tools）、资源（Resources） 和 提示模板（Prompt Templates）。 Tools 如果您熟悉大模型领域的“工具使用 (Tool Use)”，那么 MCP 中的工具概念会非常亲切。 定义：工具本质上是可由客户端调用的函数，通常用于执行修改性或写入型的操作。 功能：检索数据、执行搜索、发送消息、更新数据库记录等。 类比：可以将其理解为 POST 或 UPDATE 请求，代表着一个需要服务器去执行的“动作”。 Resources 与工具不同，资源是服务器提供的只读数据或上下文。 定义：由服务器暴露的只读数据。客户端可以选择是否使用这些资源，但不会对其进行修改。 功能：提供上下文信息，例如数据库记录、API 响应、文件内容、PDF 文档等。 类比：类似于一个 GET 请求，目的是获取“信息”而非执行操作。 Prompt Template ...

Coding Agents and AI for Vulnerability Detection

随着人工智能技术的快速发展，LLM代理正在重塑软件开发和网络安全领域。从协助程序员编写代码的智能助手，到主动发现系统漏洞的安全专家，AI代理正展现出令人瞩目的潜力。 在深入探讨具体应用之前，我们需要理解LLM代理的本质。抛开那些时髦的术语，LLM代理实际上就是具备工具使用能力的多轮对话LLM。 LLM Agent = 可以进行多轮对话的 LLM + 使用工具 (multi-turn LLMs with tool use) 这个定义强调了以下几个核心特点： 动态计算时间（Dynamic Computation Time）：与传统的一次性问答不同，LLM Agents 允许“先思考再行动”。语言模型可以在作出最终回答前进行多轮推理，动态决定需要投入多少“思维时间”，从而处理更复杂的问题。 外部工具接入（External Tools）：这使得智能体不仅限于文本生成能力，而是能与外部世界互动。比如在编程场景中，代理可以实际运行代码、观察结果，然后基于执行反馈来优化代码，这种能力对复杂的代码生成任务极其重要。 假设验证能力（Hypothesis Testing）：工具的引入还带来了实验能力。Agent 可以先提出一个假设，比如“这段代码在第13行会出错”，然后通过实际运行代码来验证自己的想法，并根据结果调整后续行为。这种“试错-修正”的机制在复杂任务中尤为关键。 行动能力（Ability to Take Actions）：如果我们希望 LLM 真正完成某项任务，它最终必须走出文本生成本身，与真实世界产生连接。而工具的接入正是这种连接的媒介。、 基于这些核心能力，我们将介绍以下三部份内容： 编程代理：如SWE（软件工程）代理，它们能够理解需求、编写代码、调试程序 AI for computer security: 利用人工智能技术来检测威胁、分析漏洞、防御攻击 专门用于安全漏洞检测的LLM代理，这是一个新兴但极具前景的应用方向，代理可以主动分析代码、发现潜在的安全风险。 在接下来的内容中，我们将深入探讨这些应用场景，看看AI代理如何在保障软件质量和系统安全方面发挥越来越重要的作用。

RAG Overview

检索增强生成（Retrieval Augmented Generation，RAG）是目前应用最广泛的技术之一，用于提升LLM的回答质量和准确性。LLM 开始仅依赖训练时的公共互联网数据，而 RAG 能通过检索外部数据源（如企业文档、专有数据）为模型提供额外信息，从而回答其未接触过的事实性问题。例如，像 ChatGPT、Claude 或 Gemini 这类聊天机器人会搜索网络以确保回答的时效性与准确性。如今，大型公司常用 RAG 为客户和员工提供精准的信息支持，而初创企业也在医疗、教育等领域构建 RAG 应用，帮助解决行业特定问题。 随着 LLM 技术的进步，RAG 系统的能力也在不断进化。新一代模型能更好地基于提供的文档进行回答，显著降低了幻觉率。同时，推理模型的兴起和 LLM 输入上下文窗口的扩大，使 RAG 的超参数调优更加精细，如选择哪些内容被检索和如何切分文档片段。 模块概览： RAG 简介：了解 RAG 的基本概念、核心价值，以及它如何提升大语言模型的回答质量 RAG 架构解析：拆解 RAG 的核心组件，包括 LLM、检索器（retriever）、向量数据库（vector database）等 应用案例：真实场景中的 RAG 系统应用，包括企业知识问答、医疗问答、教育辅导等 Introduction to RAG RAG 简介 LLM 能够回答问题、总结和改写文本、对文档提供反馈、生成代码等等。RAG是一种能够进一步提升 LLM 表现的方法，它通过为模型提供训练中未包含的外部信息来增强回答的准确性。 为了更好地理解这个概念，让我们来看几个例子： “为什么酒店在周末会更贵？” 因为周末旅行的人更多，房间竞争更激烈。 -“为什么这个周末温哥华的酒店特别贵？” 需要额外信息来回答。查阅网络后，你可能会发现国际巨星 Taylor Swift 本周末将在温哥华举办两场演唱会，有了这个信息，你就能给出答案。 “为什么温哥华市中心附近没有更多的酒店容量？” 要回答这个问题，需要深入研究温哥华的发展历史、城市规划等专业信息。换句话说，需要先获取大量的专业信息。 回答这些问题的过程可以分为两个阶段： 信息收集（retrieval）：获取必要的信息。 信息推理与回答（generation）：基于收集到的信息进行推理并生成答案。 在 RAG 中，收集信息的过程被称为 检索（retrieval），而基于这些信息生成回答的过程被称为 生成（generation）。 LLM 和人类类似，无法覆盖所有知识，尤其对近期事件或私有数据存在盲区，LLM 不知道的东西： 私有数据库：LLM 无法访问机密信息。 难以获取的信息：某些信息并不广泛公开，LLM 无法直接获得。 实时数据：LLM 的训练数据是过去的快照，它不会自动更新。 RAG 系统的关键思想就是：在将问题发送给 LLM 之前，可以先修改和增强提示词。 除了用户的原始问题，还可以加入帮助 LLM 回答的检索信息。 ...
