Prompt Engineering

Prompt Caching

我们在讨论 LLM 应用优化的时候，大多数人第一反应是换模型、调参数、改架构。但有一件事几乎被所有人忽略，它不需要改任何模型代码，不影响输出质量，却能让首 Token 延迟最高降低 80%、输出成本最高降低 90%。这件事就是 Prompt Caching。 1. Prompt Caching 基本概念 跟模型打交道，本质上就三件事可以优化：intelligence、latency、cost。三者通常此消彼长，但 Prompt Caching 是个例外：它只动后两个，完全不影响第一个。 模型的提示词中往往包含大量重复内容——系统指令、工具定义、对话历史。OpenAI 会把请求路由到最近处理过相同前缀的服务器，复用之前的计算结果，而不是从头重算。这就是 prompt caching 的本质：计算复用。 它带来的收益： 成本：cached input token 最高便宜 90%（比如 gpt-5.2 从 $1.75/1M 降到 $0.175/1M） 延迟：TTFT（首 token 时间）最高减少 80%，prompt 越长效果越明显 2. Prompt Caching 运行机制 要理解 prompt caching，需要从两个层次来看：底层（模型内部为什么能复用） 和 上层（一次 API 请求经过哪些步骤）。 2.1 底层：为什么 K/V 可以被复用 Prompt caching 能成立，根本原因要追溯到 Transformer 的核心机制：注意力（Attention）。 1.
